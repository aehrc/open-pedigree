- [x] 8.5 Found and worked around a separate, recurring GitHub Actions quirk while verifying #23: `Build`/`CodeQL`/`security-scan` land in `action_required` (needing manual approval) on release-please's own bot-authored PRs, even though they're same-repo, not fork PRs. Approved via `POST .../actions/runs/{id}/approve`. **Root cause confirmed** (David checked Settings → Actions → General directly, since org-level policy isn't visible to this session's `gh` auth without `admin:org` scope): "Require approval for first-time contributors" is enabled for fork pull request workflows, and `github-actions[bot]`'s release-please PR is apparently classified under that gate too, despite not being a literal fork PR. **Deliberately not changing this setting** — it's a legitimate security control against untrusted first-time external contributors running arbitrary CI; loosening it org- or repo-wide just to skip manually approving a handful of release-please PRs per release is a bad trade. Manual approval when it happens remains the accepted process.
