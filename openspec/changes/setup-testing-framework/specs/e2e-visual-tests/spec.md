## ADDED Requirements

### Requirement: Playwright configured with auto dev-server
The project SHALL have a `playwright.config.js` that configures `baseURL: 'http://localhost:9000'`, a `webServer` block that starts `npm start` automatically, and a screenshot directory at `tests/e2e/screenshots/`.

#### Scenario: E2E tests run via npm run test:e2e
- **WHEN** `npm run test:e2e` is executed with no dev server already running
- **THEN** Playwright starts the webpack dev server automatically
- **AND** runs all test files matching `tests/e2e/**/*.spec.js`
- **AND** shuts the dev server down when tests complete

#### Scenario: Existing dev server is reused
- **WHEN** `npm run test:e2e` is executed while `npm start` is already running on port 9000
- **THEN** Playwright reuses the existing server without starting a second instance

### Requirement: Editor load scenario tested
The file `tests/e2e/editor-load.spec.js` SHALL verify the pedigree editor loads without errors and matches a baseline screenshot.

#### Scenario: Editor renders within 10 seconds
- **WHEN** Playwright navigates to `http://localhost:9000/localEditor.html`
- **THEN** the pedigree canvas SVG element is visible within 10 seconds
- **AND** no JavaScript errors appear in the browser console

#### Scenario: Editor matches baseline screenshot
- **WHEN** the editor has fully loaded
- **THEN** a screenshot of the page matches the stored baseline within a 2% pixel difference threshold

### Requirement: Add person node scenario tested
The file `tests/e2e/add-node.spec.js` SHALL verify that clicking to add a person node results in a new node appearing in the SVG.

#### Scenario: New person node appears after click
- **WHEN** the user clicks the "add person" action in the editor toolbar
- **THEN** a new person node SVG element appears in the pedigree canvas
- **AND** the node count in the SVG increases by 1

#### Scenario: Add-node state matches baseline screenshot
- **WHEN** a person node has been added
- **THEN** a screenshot matches the stored baseline within a 2% pixel difference threshold

### Requirement: JSON save/load scenario tested
The file `tests/e2e/save-load.spec.js` SHALL verify that a pedigree can be serialised and the exported JSON structure is valid.

#### Scenario: Export JSON contains expected structure
- **WHEN** the editor's export function is triggered for the internal JSON format
- **THEN** the resulting JSON contains a `GG` (graph) key with node data

### Requirement: Export formats produce downloadable files
The file `tests/e2e/export-formats.spec.js` SHALL verify that the PED, DADA2, GA4GH FHIR, and SVG export buttons each trigger a file download without errors.

#### Scenario: PED export triggers download
- **WHEN** the user opens the export dialog and selects PED format
- **THEN** a file download is triggered with no JavaScript errors

#### Scenario: DADA2 export triggers download
- **WHEN** the user opens the export dialog and selects DADA2 format
- **THEN** a file download is triggered with no JavaScript errors

#### Scenario: GA4GH FHIR export triggers download
- **WHEN** the user opens the export dialog and selects GA4GH format
- **THEN** a file download is triggered with no JavaScript errors

### Requirement: Baseline screenshots committed to repository
Baseline screenshot files (`.png`) generated by the first Playwright run SHALL be committed to `tests/e2e/screenshots/` in the git repository so that future runs can diff against them.

#### Scenario: Baselines exist after initial setup
- **WHEN** `npm run test:e2e -- --update-snapshots` is run for the first time
- **THEN** `.png` baseline files are created in `tests/e2e/screenshots/`
- **AND** those files are tracked by git

#### Scenario: Regression detected on visual change
- **WHEN** a code change alters the visual appearance of the editor
- **THEN** `npm run test:e2e` fails with a screenshot diff report showing the changed pixels
