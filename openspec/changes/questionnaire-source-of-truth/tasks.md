Also found and fixed, in the same investigation: `setDisorders`/`setGenes`/`setPhenotypes` themselves threw when passed the `questionnaire-legend-picker`'s native `{system,code,display}` answer shape (they only handled raw ID strings or pre-resolved Term objects) - added a shared `normalizeLegendAnswerIds()` helper in `person.ts` rather than renaming the setters (renaming would have silently broken `controller.ts`'s hardcoded `setDisorders`/`setCarrierStatus` undo-cascade string matching).
